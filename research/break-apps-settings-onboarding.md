# 对标调研：休息提醒类产品怎么设置 & 怎么问用户

调研时间：2026-07-01
方式：agent-reach（GitHub 源码 + Exa 网页搜索 + GitHub issues 里的真实用户反馈）

## 一句话结论

**这个品类几乎没人做“上来就问卷式个性化”。** 统一套路是：**给一套好默认值 → 首启只给个 Welcome（选语言/看教程/直接用默认）→ 之后随便改 → 靠活动感知和习惯养成来贴合用户。**

我们最终仍选择做完整问卷 onboarding（产品差异 + 自媒体素材价值），但用调研教训做了约束：每题都映射到真实行为、可跳过、不问废话。

## 依据一：开源默认值（可直接抄）—— stretchly `defaultSettings.js`

两级休息结构（整个品类通用）：

| 项 | 默认值 |
| --- | --- |
| 微休息 microbreak | 20 秒 / 每 10 分钟 |
| 长休息 break | 5 分钟 / 每 30 分钟（每 2 次微休息后） |
| 提前预告 | 微 10 秒 / 长 30 秒 |
| 推迟 postpone | 只能推 1 次；微 2 分 / 长 5 分 |
| 自然休息 naturalBreaks | 空闲 >20 秒算休息中；空闲 >5 分钟重置计时 |
| 严格模式 strictMode | 可选，禁止跳过 |
| appExclusions | 指定 App 里不弹（如会议/游戏） |
| monitorDnd | 跟随系统勿扰 |

`naturalBreaksManager.js` 用 `powerMonitor.getSystemIdleTime()`——**和我们“等 AI”同源**，我们多加了“前台是编码工具”这层。

## 依据二：休息时“做什么”——分两层，且大多不做详细步骤

- 微休息 = 一句话动作：“去接杯水”“慢慢看左再看右”“伸展手臂”“检查坐姿”“看 20 米外”。
- 长休息 = 偏科普/引导：为什么要休息、人体工学、冥想、久坐危害。
- 每条可单独开关，随机轮播；**无个性化推荐，靠用户手动禁用不喜欢的。**
- 我们的 23 个动作带详细步骤 + 注意事项，比它们更细——是优势，别丢。

## 依据三：真实用户痛点（GitHub issues，设计雷区）

- **提醒时机不对**（[stretchly #1560](https://github.com/hovancik/stretchly/issues/1560)）：上完厕所回来它正要弹，因“最后输入后 5 分钟算活跃”的粗糙判断。→ 纯空闲检测会误判。
- **习惯性跳过**（[workrave-website #6](https://github.com/rcaelers/workrave-website/issues/6)）：一个老用户从番茄钟节奏起步，天天 postpone、烦到不行，折腾几周才摸到合适节奏。教训：爱跳过的休息，要么删要么强制，别温水煮青蛙。**也说明上来问用户，他只会瞎填。**
- **打扰程度两极分化**（[stretchly #1561](https://github.com/hovancik/stretchly/issues/1561)）：有人要全屏强制，有人开会被挡暴怒要小窗。→ 打扰强度应可配。
- **开会/看视频别弹**：所有商业新品（LookAway/DeskRest/SmartPause/Keybreak）都主打活动感知 + App 排除名单，Zoom/YouTube/游戏时自动暂停。

## 依据四：商业新品的定位关键词

“smart / 活动感知 / gentle unobtrusive / 引导式针对身体部位的拉伸 / streak 习惯养成 / 等你开完会再提醒”。这些正好印证我们“等 AI + 灵狐陪伴 + 详细动作”的方向。

## 我们的落地方案

- **完整问卷 onboarding**（5 题）：最累部位（多选，加权动作库）/ 工作节奏 / 提醒频率 / 打扰强度 / 每次时长；末尾可选勿扰时段。可随时“跳过用默认”。
- 答案 → 设置补丁 + 用户画像（`store.js` 的 `onboardingToConfig`）。
- 动作推荐用**加权随机**（命中痛点加权、超时降权），软偏好保留多样性（`reminder-engine.js` 的 `pickExercise`）。

## 下一步（未做）

- **行为自适应**：按完成/跳过数据动态调权重（总跳过肩颈就少推；某时段总跳过就降频）。这才是真正的个性化，调研一致指向这条路。
- App 排除名单（开会/看视频不弹）。
- 两级休息（微 + 长）拆分。
